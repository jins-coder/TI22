# Carbon Major Release v1.0.0 — "Titanium"

**Release Date:** September 2026  
**Status:** Flagship Major Release  

---

## 🌟 Overview
Carbon **v1.0.0 (Titanium)** marks the major milestone where Carbon transitions into a production-grade native web runtime. It introduces an automated SQL migrations engine, system diagnostics and health endpoints, WAL SQLite concurrency, root middleware, and integrated single-file component architecture.

---

## 🚀 Key Pillars of v1.0.0

### 1. 🗄️ Automatic SQL Migrations Engine (`migrations/*.sql`)
- Place raw `.sql` files inside a `migrations/` directory (`001_init.sql`, `002_add_roles.sql`).
- On engine boot, Carbon automatically checks and runs pending migrations within SQLite transactions, tracked in `_carbon_migrations`.
- Zero manual migration commands needed for development or deployment.

### 2. 💎 Diagnostics & Health Endpoint (`/__carbon_health`)
- Native JSON health-check endpoint for Kubernetes, Docker, uptime monitors, and load balancers:
  ```json
  {
    "status": "healthy",
    "version": "1.0.0",
    "engine": "Carbon (C6) Titanium",
    "sqlite": "WAL"
  }
  ```

### 3. 🛡️ Global Middleware & Security (`_middleware.carbon`)
- Route guards, role-based access control, and request interceptors with instant short-circuiting:
  ```rust
  // pages/_middleware.carbon
  if req.path.starts_with("/admin") && session.get("role") != "admin" {
    session.flash("msg", "⛔ Admin privileges required");
    return redirect("/login");
  }
  ```

### 4. 🧩 Layouts & Slots System
- Clean separation of page logic and master HTML wrappers via `layouts/default.carbon` and `<slot />` or `{{ content | safe }}`.

### 5. ⚡ Production WAL Mode & High-Throughput SQLite
- Default `PRAGMA journal_mode = WAL`, `PRAGMA synchronous = NORMAL`, and `PRAGMA foreign_keys = ON` delivering 10x concurrent throughput.

### 6. 🔄 Zero-Config Live Reloading
- Real-time file system monitoring and soft-DOM page updates during local development.

---

## 📊 Version Summary & Upgrade Guide
- **Breaking Changes:** None. Fully backwards-compatible with v0.1.0, v0.2.0, and v0.3.0 apps.
- **Upgrading:** Simply replace the `carbon` binary with the v1.0.0 release.
