Prologue

Architecture & Philosophy

Why Titanium replaces the fragmented modern web stack with a unified single binary.

Modern web development is often bogged down by heavy, fragile microservices: separate Node.js or Python runtime engines, external Redis servers, PostgreSQL/MySQL clusters, NGINX reverse proxies, WebSocket daemons, task queue workers, and gigabytes of node_modules.

Titanium (Ti22) rewrites this paradigm. Written in high-performance bare-metal Rust, Titanium compiles your entire web application into a single zero-dependency binary with sub-millisecond response times.

⚡ Zero Dependencies

Compiles directly to native machine code. No Node.js, V8, Python, or Ruby interpreter needed.

🗄️ Embedded Concurrency

SQLite in WAL mode executes queries in sub-millisecond memory-mapped pages with zero network hops.

🌐 Complete Tooling

Built-in WebSockets, In-Memory TTL Cache, Task Queues, AI Agents, and Cluster WAL Sync.

Why the name Titanium (Ti22)? Named after Element 22 on the periodic table — renowned for its extraordinary strength-to-weight ratio, high corrosion resistance, and aerospace durability. Titanium brings those exact engineering qualities to web application development.

Installation & Setup

Get up and running with a Titanium project in less than 30 seconds.

1. Initialize a New Project

Clone or initialize a new repository and compile with Cargo:

Terminal 
# Clone repository
git clone https://github.com/jins-coder/TI22.git my-app
cd my-app

# Run server with live auto-reload
cargo run --bin titanium

2. Directory Structure

Titanium follows a clean, convention-over-configuration layout:

my-app/
├── titanium.toml          # Central configuration file
├── routes/                # Dynamic script endpoints (.rhai or .rs)
│   ├── index.rhai         # Root route (/)
│   ├── api/
│   │   ├── users.rhai     # REST API (/api/users)
│   │   └── chat.rhai      # AI Streaming & WebSockets
├── views/                 # HTML templates & layouts
│   ├── layout.html        # Master wrapper template
│   └── home.html          # View content
├── public/                # Static assets (CSS, JS, SVG images)
│   ├── favicon.svg
│   └── app.css
└── data/                  # Embedded SQLite database & WAL logs
Configuration

Configuration (titanium.toml)

Tune runtime thread pools, database connections, AI keys, and cluster mesh settings.

titanium.toml 
[server]
host = "127.0.0.1"
port = 8080
workers = 8
public_dir = "public"
routes_dir = "routes"

[database]
path = "data/app.db"
max_connections = 32
wal_mode = true

[cluster]
enabled = true
node_id = "node-alpha-1"
is_primary = true
peers = ["http://127.0.0.1:8081", "http://127.0.0.1:8082"]

[ai]
provider = "gemini"
api_key = "env:GEMINI_API_KEY"
default_model = "gemini-1.5-flash"

Basics

Routing & Dynamic Endpoints

File-based routing with automatic parameter extraction and JSON responses.

routes/api/users.rhai 
// Fetch query params or JSON body
let role = req.query("role");
let limit = req.query_int("limit") || 10;

// Fetch active users with ActiveRecord ORM
let users = model("User")
    .where("role", "=", role)
    .order_by("created_at", "DESC")
    .limit(limit)
    .get();

// Return JSON response with HTTP 200
return json(#{
    status: "success",
    count: users.len(),
    data: users
});
Database & ORM

ActiveRecord Query Builder

Fluent, chainable ORM designed for high-speed expressive data manipulation.

ActiveRecord Examples 
// 1. Insert Record
let new_id = model("User").create(#{
    name: "Alex Mercer",
    email: "alex@titanium.dev",
    role: "admin",
    created_at: time_now()
});

// 2. Complex Query Filtering
let admins = model("User")
    .where("role", "=", "admin")
    .where("active", "=", 1)
    .order_by("id", "DESC")
    .limit(20)
    .get();

// 3. Update Record
model("User").where("id", "=", new_id).update(#{
    role: "superadmin"
});

// 4. Delete Record
model("User").where("active", "=", 0).delete();
Database

Raw SQLite & Atomic Transactions

Execute raw SQL queries with parameter binding and ACID transactions.

Database Transactions 
// Begin Atomic Transaction
db_begin();

try {
    db_exec("UPDATE accounts SET balance = balance - 100 WHERE id = ?", [from_id]);
    db_exec("UPDATE accounts SET balance = balance + 100 WHERE id = ?", [to_id]);
    db_commit();
    return json(#{ status: "transferred" });
} catch (err) {
    db_rollback();
    return json(#{ error: "Transfer failed: " + err });
}
